# Design tools (930 / 1130)

Prerequisite: this repo, Node >= 20, the `design:*` npm scripts. Design roots:
`docs/ui/source/1130` (the scripts' default) and `docs/ui/source/930` (first-class batch —
pass it as the trailing root argument). Per screen: `arkUIDSL.json` (node tree: `meta.octoName`,
`meta.bbox`, `content`, `src`, `styles`), `screenshot.png` (the design's own render),
`index.html` (sanitized stock export). Shared: `_shared/fonts/`, `_shared/tailwind-play.js`,
`_shared/assets/` (deduped assets). The per-batch section of `docs/ui/DESIGN_INDEX.md` is the
machine index (regenerated by the sanitizer). `dsl.json` / `index.ets` / zips are dropped.

## 1. Ingest a fresh export (the only command you need for a new zip)

```sh
npm run design:sanitize -- <path-to.zip>
```

One command does the whole flow and verifies itself:

1. Extract the zip into `docs/ui/source/<batch>/` (the zip's basename, e.g. `1130`); a
   single top-level folder inside the archive is unwrapped automatically.
2. Fix every screen's `index.html`: tailwind ref → local `../_shared/tailwind-play.js`
   (copied from an existing batch's `_shared/` or `--tailwind-src <file>`), `@font-face`
   urls → `../_shared/fonts/` (fonts hoisted per-screen into `_shared/fonts/`), remove the
   24px canvas margin (`m-[24px]` — otherwise the whole stock render sits shifted +24/+24),
   and compact the inter-tag newline/indent whitespace (~25% of the file; single-space
   separators between inline elements are preserved).
3. Drop `dsl.json` / `index.ets` (unused).
4. **Lossless size optimization** (no quality loss, verified per file):
   - PNG (assets **and** design screenshots — the exporter stores them with a weak deflate):
     re-deflate IDAT at level 9 (several strategies, smallest wins); the filtered scanlines
     are preserved byte-for-byte and the new stream is inflated back and compared before
     writing. Colour-relevant chunks are kept; text/time chunks drop. Measured on the 1130
     batch: screenshots saved 12.63 MB; asset PNG/SVG recompression saved another 7.99 MB.
   - SVG: comments/metadata out, inter-tag whitespace collapsed, numbers normalized without
     changing their value (`28.000000`→`28`), unused `xmlns:xlink` and the non-standard
     `customFrame` attribute dropped. Each candidate is rasterized before/after with sharp
     and pixel-compared; failures keep the original.
   - Unused icon font: when no design text uses HMSymbol private-use glyphs (U+F0000–F126D),
     `_shared/fonts/HMSymbolVF.ttf` and its `@font-face` blocks are removed (~4 MB).
   - `arkUIDSL.json` is minified at the end (whitespace is ~80% of the file: 24.9 MB saved
     across the batch) — parse it with a tool, not by eye.
   Whole-batch result: 226 MB of raw export → **42 MB** on disk (6129 files).
5. **Dedupe assets**: identical files across screens (same name + size + md5) move to
   `_shared/assets/` and every reference in `arkUIDSL.json` + `index.html` is rewritten to
   `../_shared/assets/<name>` (exact-pattern replaces, idempotent). Same-name-different-
   content files stay in their screen's `assets/` (collision — the screens come from
   different design revisions). Re-runs never overwrite already-shared content.
6. **Adopt shared assets by name**: screens exported without their own `assets/` get every
   ref whose file name exists in `_shared/assets/` rewired to `../_shared/assets/<name>`
   (same Octo node id within one design revision ⇒ same graphic).
7. **Recover assets by structure**: refs that exist nowhere under their own name are matched
   against every other screen's asset-bearing nodes. Candidates = same `octoName` + rounded
   size + file extension, absolute position within **±4 px** (revisions routinely shift
   elements by 1–2 px); ranked per content md5 by (a) the smallest position shift,
   (b) matching nearest-ancestor name, (c) closest pageId (neighbouring design states are
   the best donors — e.g. ReferenceInvoked ← ReferenceNotInvoked, CannWorkInvokedLoggedIn ←
   CannWorkButtonIdle), (d) frequency. The ref points at the **donor's own name** in
   `_shared/assets/` — no per-screen alias copies (an alias under the screen's name is only
   created for a name collision with different content, and only when the alias name is
   free or already holds the donor's bytes). Validated leave-one-screen-out over the
   25-screen revision that first shipped the matcher: zero screens regressed, +16 correct
   picks vs an exact-position matcher. `--self-check CannWorkButtonIdle` prints the current
   numbers (assets 255, structurally covered 254, truth among candidates 248 — the ceiling,
   since some assets changed between revisions, picked correctly 219 = 86.2%). Whatever
   still cannot be matched stays in the export-gaps table.
   Worked example (the earlier revision, where five screens arrived without assets):
   CannWorkInvokedLoggedIn 173→10 missing,
   CannWorkInvokedLoggedOut 164→9, DocumentSearch 215→19, ReferenceInvoked 241→19,
   ContextReference 243→21 (nearly all of its popup chrome matched at a 1 px shift).
8. **Invalid screenshots**: a `screenshot.png` whose size differs from the page canvas is an
   export defect (a popup crop, not the full screen) — it is removed and named in the
   export-gaps table (the earlier 1130 revision shipped 262×439 crops for ContextReference
   and ReferenceInvoked; the current export is full-canvas). Recovery for such screens
   proceeds from the structure only, not from the screenshot.
9. **Verify**: render + pixel-diff every screen before and after the dedupe
   (`design:diff --all --json` twice) and fail if any screen got worse than +0.05pp.
   Rendering runs on 6 concurrent pages (`--concurrency N`), so a full pass is fast.
10. Regenerate the batch's section of `docs/ui/DESIGN_INDEX.md` (screens table + export gaps,
    pageIds preserved; the table width follows the columns actually emitted).
11. Cleanup: temporary `_rebuilt.html` renders (from `design:render` / the diff verification)
    are removed — the sanitized stock `index.html` is the only html kept in the repo.
12. Delete the zip on success (keep with `--keep-zip`).

Speed notes: the zip is extracted with Windows' `tar.exe` when it understands zips (falls
back to `Expand-Archive`); SVG optimization verification runs on a pool of 8; screen
rendering in `design:diff` runs on 6 concurrent browser pages (a full 26-screen pass takes
~20 s).

Self-check the structural matcher at any time (uses the screen's own assets as ground truth;
temporarily remove it from the donor pool):

```sh
npm run design:sanitize -- --self-check CannWorkButtonIdle
# self-check CannWorkButtonIdle: assets 255 | structurally covered 254 | truth among candidates 248 | picked correctly 219
```

Re-runs: `npm run design:sanitize -- docs/ui/source/1130` (check-only report) or `--fix`
(re-run fixes + dedupe + verify; idempotent). `--skip-verify` skips the diff passes.

## 2. Locate a UI element (the common flow)

```sh
npm run design:find -- "UB" --word          # exact word; without --word it is substring
npm run design:find -- "内存负载" --screen BaselineAddAndSelectGuide
npm run design:find -- "UB" --word docs/ui/source/930   # 930 batch (default root is 1130)
```

Output: per screen, matched nodes with type, name, bbox, text/src, and the **ancestor chain**
(e.g. `基线对比数据 > … > 内存负载分析 > 组合 91334743 > AIV1 > …`). Then map to code with the
table below, render the screen (`design:render <Screen>`, opens `_rebuilt.html`), and if
needed `design:diff <Screen>` to see how far the current render is from the design.

| Design name (octoName) | Code |
|---|---|
| `报告统计` (right panel) | `src/ui/StatsAside/StatsAside.vue` |
| `内存负载分析…` (UB/L0A/L0B/L0C units) | `src/ui/StatsAside/MemoryTopologyPanel/` (+ fullscreen overlay, `MemoryHeatmapPanel`) |
| `时钟周期` rows (Vector/MTE2/MTE3/Scalar/SIMT/SIMD) | `src/ui/StatsAside/` summary category list |
| Roofline / 曲线 charts | `src/ui/StatsAside/RooflinePanel/` |
| PIPE occupancy | `src/ui/StatsAside/PipeOccupancyPanel/` |
| CSV field lists | `src/ui/StatsAside/CsvFieldListPanel/` |
| hardware details | `src/ui/StatsAside/HardwareDetailsPanel/` |
| `统计分析` toolbar row (Cube/Vector toggle) | `src/ui/ReportToolbar/` |
| `泳道`/`g`/`线`/`刻度` (swimlane charts) | `src/ui/TimelineView/` + `src/swimlane/` |
| `OP算子` / 源码 code panes | `src/ui/SourceView/` |
| `提示悬浮` (hover tooltip) | `src/ui/EventTooltip/` |
| `顶部菜单栏`/`底部栏`/`菜单` (chrome) | host (`report-shell`), not this library |

Design is ahead of code in places (1130 redesign) — treat the mapping as the closest
component, and check its `spec.md`/`visual/` pack before touching code.

## 3. Render + diff

```sh
npm run design:render -- <Screen>        # arkUIDSL.json -> <Screen>/_rebuilt.html
npm run design:diff -- <Screen>          # render + pixel diff vs screenshot.png
npm run design:diff -- --all             # every screen with a screenshot (table)
npm run design:diff -- --all docs/ui/source/930   # same for the 930 batch
```

`_rebuilt.html` is a working artifact for verification only — do not commit it; the sanitizer
removes it at the end of every `--fix` run (the sanitized stock `index.html` is the only html
kept). Diff columns: `noticeable` = % pixels with RGB-sum delta > 90, `strong` = > 270.
Screens without a screenshot, or whose screenshot size ≠ the canvas, are skipped.
Baseline: most screens 3–4% noticeable / ~1% strong; source-code screens up to ~9% (code
text is one green block in the DSL while the screenshot has syntax colors — export loss).
The renderer (`scripts/design-render.mjs`) is the reference implementation of the DSL;
the residue is composite-asset color drift and font raster mismatch, not layout.

## 4. Pitfalls (do not re-learn)

- Colors are `#AARRGGBB` (alpha first) — convert to `rgba()`; browsers read 8-digit hex alpha-last.
- `styles.marginTop/marginLeft` are auto-layout offsets already baked into `meta.bbox` — never apply both.
- Text boxes are sometimes narrower than the text — texts must not wrap (`white-space:pre`), except when the box is taller than one line (`height > lineHeight + 1` → `pre-wrap` + `word-break:break-word`, matching the stock export).
- The flat DOM loses ancestor clipping and group opacity: rounded ancestors must clip descendants (`clip-path`), group `opacity` must multiply down the tree.
- Small raster tiles in large boxes render at natural size, centered, no-repeat (the stock html does); stretched composites use `object-fit:fill`.
- Every value interpolated into a `style` attribute or a `src` is passed through `escAttr` (`&`, `<`, `>`, `"`); `background-image` uses `JSON.stringify(src)`. Never interpolate a raw DSL string into HTML without it.
- The full-page annotation dim (`#66262626`) is a design-tool layer; the stock render drops it — skip it.
- Full-page mask `Image` nodes (弹窗遮罩) dim the app behind a modal: render the image but ignore its export `backgroundColor` (it double-darkens: measured 8 vs the design's 22). Raise modal containers (octoName ending in `弹窗` / `对话框`) into the floating layer so the mask never covers them — the mask name (`弹窗遮罩/Dark`) must NOT match that rule.
- `蒙版` nodes are only sometimes invisible: a shape-only mask group (no image anywhere in its subtree) is dropped like the stock html; a `蒙版` with images inside is a clipping viewport whose subtree IS the visible content — render it.
- Exports can arrive without `assets/` (the earlier 1130 revision had five such screens: ContextReference, ReferenceInvoked, CannWorkInvokedLoggedIn/Out, DocumentSearch). Name adoption + structural recovery fill most of them (see the flow); whatever is left is listed in the export-gaps table in `DESIGN_INDEX.md`. The current 1130 export has none missing.
- Design `screenshot.png` is RGBA; diff buffers must use each image's own channel count.
- The export writes `"src": "assets/…"` with a space after the colon; the sanitizer minifies `arkUIDSL.json` at the end, producing `"src":"assets/…"` — rewrite patterns must match both formattings.
- The screenshot's text raster is ~2–3% narrower than the provided `HarmonyOS_Sans_SC_Medium.woff2` (the design tool used a different font) — a known residual, not a layout bug.
